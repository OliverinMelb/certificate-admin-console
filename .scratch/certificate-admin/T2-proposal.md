# T2 批量发证与审计方案

状态：用户已批准实现。确认原文：“批准两项并行（含撤销后不重发）”；T1 浏览器验收通过后，用户再次要求按已确认方案并行开发 T2、T5。基于 T1 的六表、演示身份、读取接口。

## 行为与技术决定

- 已完成报名且该租户/课程/学员从未获证者可发证；未完成与已有证书者跳过。建议撤销后不重新发证，本版本不做证书版本链；这是须确认的业务取舍。
- 新增 UNIQUE(tenant_id, course_id, learner_id) 索引，数据库兜底防重。若现有文件库存在重复数据，初始化明确报错，不能自动删数据。
- 每批一个短写事务，BEGIN IMMEDIATE；每个学员使用 SAVEPOINT，证书与 ISSUED 审计一起成功或一起回滚。整批基础设施异常回滚并返回非成功HTTP；不伪造已持久化的逐人成功结果。
- 仅针对明确可恢复的逐项异常返回 failed；重复约束冲突解释为 skipped/already_certified；不能把所有数据库异常吞成 failed。首次最小实现无需制造人工失败开关或额外业务校验。
- Certificate编号用UUID生成，保持现有唯一约束；issued_at 使用带UTC语义的ISO字符串，继续与T1一致。T2不存当地日期，不依赖T5实现。
- 新增 audit_event，记录 tenant、certificate、actor、event_type、occurred_at。证书与事件类型唯一；预留 REVOKED 事件类型，但本项不实现撤销。租户关联由复合约束与服务端校验共同维护。
- 新增 POST /api/courses/{id}/issue，演示身份校验沿用T1。跨租户或不存在课程同404且无证书/审计副作用。返回 {course_id, outcomes:[{learner_id,outcome,reason,certificate_id}]}，outcome为issued/skipped/failed。
- 新增只读 GET /api/certificates/{id}/audit，沿用详情权限，不存在/越租户404；用于管理员核对及公共接口验收。T4复用此接口。
- 前端选择课程并点击批量发证；提交中禁用按钮、显示进度状态；完成后显示逐人结果和原因，刷新当前列表。切换身份忽略旧操作响应并清空旧结果。
- T3再实现 Idempotency-Key 持久化和结果重放。T2的数据库防重不等于A2已通过，也不承诺网络超时后得到原始操作结果。

## 测试边界

真实文件SQLite支撑的HTTP API；通过证书列表/详情/审计接口观察结果，不断言内部SQL或函数调用次数。

1. 混合报名只对合格者issued；未完成/已有证书skipped且有原因；返回覆盖课程报名学员。
2. 每次真实发证一条ISSUED审计；重复发证无重复证书或审计，第二次结果可为skipped（T3才保证原结果重放）。
3. 跨租户请求404，合法所属租户查询证实无副作用。
4. 在数据库故障夹具中验证证书与审计原子性，确保失败不留下半条业务结果；测试安排故障可在测试层完成，不能向产品增加故障开关。
5. 浏览器课程选择、提交禁用、逐人结果、列表刷新、错误提示与切换身份隔离。

## 并行边界

依赖T1完成。可以与T5并行：T2拥有发证/审计服务、对应迁移与测试、BulkIssue组件；T5拥有时间转换、列表日期查询/展示及测试。主线程拥有共享路由装配、数据库初始化挂接、页面入口和公共类型集成；先固定模块接口再启动writer，避免两人编辑相同文件。

T2完成后T3和T4可基于同一稳定证书/审计模型并行，各自仍须方案确认。
